# Конституция проекта «Зырик»

Принципы, которым обязаны соответствовать все спецификации, планы и код.
Изменение конституции — отдельный осознанный шаг с записью в журнале версий внизу.

## I. Безопасность прежде всего (модель «как у Зябры»)

Это главный принцип; при конфликте с любым другим побеждает он.

- **Не открывает сеть.** Никаких обновлений, телеметрии, облаков, загрузки моделей или словарей.
  На Linux допустимы только местные сокеты (сервер X, D-Bus / xdg-desktop-portal).
- **Не пишет на диск без явной команды.** Снимок живёт только в памяти. Файл появляется
  только по Ctrl+S. Никаких временных файлов, истории, кэша миниатюр, логов с содержимым.
- **Буфер обмена — единственное исключение.** Готовый снимок кладётся в буфер: это основной
  сценарий. Но по возможности — так, чтобы он не попадал в историю буфера и облачную синхронизацию ОС.
- **Не добавляет себя в автозагрузку.** Обычный видимый процесс со значком в трее, не служба.
- **Скрытие данных необратимо.** Закрашенное нельзя восстановить ни из буфера, ни из файла.
- **Память чистится.** После копирования или отмены изображение и пометки удаляются из памяти.

## II. Мгновенность

От нажатия горячей клавиши до появления рамки выделения — не дольше 200 мс.
В простое программа не нагружает систему (~0% CPU, десятки МБ памяти).

## III. Клавиатура прежде всего

Любое основное действие доступно с клавиатуры. Мышь — удобство, а не требование.

## IV. Минимум трения

- Основной сценарий «выделил → в буфере» — без лишних кликов и диалогов.
- Один исполняемый файл на платформу, без установки (portable).
- Разумные значения по умолчанию.

## V. Одинаково на трёх платформах

Windows 10/11, Linux (X11 и Wayland), macOS. Поведение и клавиши совпадают, насколько
позволяет ОС; платформенные ограничения честно описываются в README.

## VI. Характер, но без навязчивости

Зырик — персонаж с юмором (рожица «о_О»: один глаз обычный, другой вытаращен — «зырнул»), но шутки не мешают работе:
никаких всплывающих окон ради шутки и звуков по умолчанию.

## VII. Простота

Делаем меньше, но хорошо. Минимум зависимостей. Новая функция появляется только
со своей спецификацией и только если не нарушает принципы I–VI.
