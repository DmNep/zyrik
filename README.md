# Зырик

Программа для снимков экрана: зырк на кусок экрана — и он уже в буфере.

Проект ведётся по **Spec-Driven Development (SDD)**: сначала спецификация,
потом план, потом задачи, и только потом код.

## Сборка и запуск (Windows)

Нужны Rust (stable, тулчейн `x86_64-pc-windows-gnu`) и `windres` из MinGW: им в exe вшиваются значок и версия.

```
cargo test
cargo build --release
target\release\zyrik.exe --help
```

Сейчас (фаза 2): Ctrl+PrtScr → выделить мышью (стрелки двигают, Ctrl+стрелки меняют размер) → Enter или Ctrl+C — снимок в буфере, с пометкой «не в журнал Win+V и не в облако». Снимок одноразовый: вставили через Ctrl+V и отпустили Ctrl — буфер пуст (пока Ctrl зажат, можно вставить ещё раз). Фоновые программы, читающие буфер, снимок не получают. Esc — отмена. После выделения появляется панель:
- инструменты: карандаш (P), линия (L), стрелка (A), прямоугольник (R), подпись (T);
- цвет: красный или синий (C);
- колёсико меняет толщину или размер подписи; Ctrl+Z / Ctrl+Y — отменить и вернуть;
- Ctrl+S — сразу PNG без метаданных в последнюю папку (`--save-dir` или «Изображения»);
- дискета — свой выбор папки прямо поверх снимка: ↑↓ и Enter — по папкам, Backspace — вверх, буква — к папке на эту букву, Ctrl+S — сохранить сюда, Esc — назад. Системный диалог Windows не используется: он записывает в реестр имя программы и последнюю папку.

Поиск приватных данных — следующие фазы.
Настройки — только параметры запуска, см. `--help`.

## Linux (X11)

Сборка: `cargo build --release` (ничего, кроме Rust, не нужно: X11 и D-Bus — на чистом Rust).
Нужен X-сервер на этой же машине (`DISPLAY=:0`); X по сети и Wayland — пока нет (Wayland — фаза 5).
Значок в трее — StatusNotifierItem (KDE, XFCE, Cinnamon; GNOME — с расширением AppIndicator). Нет трея — работает горячая клавиша.
Проверка в контейнере: `docker build -t zyrik-x11 tools/linux-test && docker run --rm -v "$PWD:/src:ro" zyrik-x11`.

## Структура

| Путь | Что там |
|---|---|
| `memory/constitution.md` | Принципы проекта — то, что не обсуждается в каждой фиче |
| `specs/NNN-<фича>/spec.md` | **Что** и **зачем** делаем (без технологий) |
| `specs/NNN-<фича>/plan.md` | **Как** делаем: стек, архитектура (появится после утверждения спеки) |
| `specs/NNN-<фича>/tasks.md` | Пошаговые задачи для реализации (после плана) |

## Порядок работы

1. **Specify** — пишем `spec.md`, закрываем все `[НУЖНО УТОЧНИТЬ]`.
2. **Plan** — выбираем стек и архитектуру, пишем `plan.md`, сверяем с конституцией.
3. **Tasks** — разбиваем план на `tasks.md`.
4. **Implement** — пишем код строго по задачам.
