# Зырик

Программа для снимков экрана: зырк на кусок экрана — и он уже в буфере.

Проект ведётся по **Spec-Driven Development (SDD)**: сначала спецификация,
потом план, потом задачи, и только потом код.

## Сборка и запуск (Windows)

Нужны Rust (stable, тулчейн `x86_64-pc-windows-gnu`) и `windres` из MinGW: им в exe вшиваются значок и версия.

```
cargo test
cargo build --release
target\release\zyrik.exe --help
```

Сейчас (фаза 2): Ctrl+PrtScr → выделить мышью (стрелки двигают, Ctrl+стрелки меняют размер) → Enter или Ctrl+C — снимок в буфере, с пометкой «не в журнал Win+V и не в облако». Снимок одноразовый: вставили через Ctrl+V и отпустили Ctrl — буфер пуст (пока Ctrl зажат, можно вставить ещё раз). Фоновые программы, читающие буфер, снимок не получают. Esc — отмена. Пометки, сохранение в файл и поиск приватных данных — следующие фазы.
Настройки — только параметры запуска, см. `--help`.

## Структура

| Путь | Что там |
|---|---|
| `memory/constitution.md` | Принципы проекта — то, что не обсуждается в каждой фиче |
| `specs/NNN-<фича>/spec.md` | **Что** и **зачем** делаем (без технологий) |
| `specs/NNN-<фича>/plan.md` | **Как** делаем: стек, архитектура (появится после утверждения спеки) |
| `specs/NNN-<фича>/tasks.md` | Пошаговые задачи для реализации (после плана) |

## Порядок работы

1. **Specify** — пишем `spec.md`, закрываем все `[НУЖНО УТОЧНИТЬ]`.
2. **Plan** — выбираем стек и архитектуру, пишем `plan.md`, сверяем с конституцией.
3. **Tasks** — разбиваем план на `tasks.md`.
4. **Implement** — пишем код строго по задачам.
