# План реализации 001: Базовый захват экрана

**Спека**: [spec.md](spec.md) · **Статус**: черновик · **Создан**: 2026-11-20

> План отвечает на вопрос **как**. Всё, что здесь помечено `[ИССЛЕДОВАТЬ]`, проверяется
> прототипом до начала соответствующей фазы; результат записывается в раздел «Исследования».

## Кратко

Rust, один исполняемый файл на платформу, своя тонкая прослойка под каждую ОС — как в Зябре
(`src/win`, `src/mac`, `src/linux`). Всё, что не зависит от ОС (рисование пометок, поиск «опасного»,
PNG, параметры, языки), — общее ядро на чистом Rust, покрытое тестами без графики.

## Технический контекст

| | |
|---|---|
| **Язык** | Rust (stable), edition 2021 — как Зябра; общий опыт и CI |
| **Платформы** | Windows 10/11 x64; Linux x86_64 (X11, Wayland: Sway, Hyprland, KDE, GNOME); macOS 14+ Apple Silicon |
| **Поставка** | Windows: `zyrik.exe`; Linux: один бинарник; macOS: см. решение D7 |
| **Хранение** | Никакого. Всё в памяти; на диск — только PNG по Ctrl+S |
| **Сеть** | Запрещена, проверяется в CI (см. «Проверки») |
| **Тесты** | `cargo test` для ядра; ручные чек-листы по платформам; автоматическая проверка «нет записи на диск и нет сети» на Linux |
| **Цели** | Режим выделения ≤ 200 мс; простой ≈0% CPU, ≤ 50 МБ; бинарник ≤ 20 МБ (из них ~10–12 МБ — встроенный OCR: модели tessdata_fast eng 4,1 МБ + rus 3,9 МБ и код Tesseract/Leptonica ~3–5 МБ — оценка, уточнить в R4) |

## Архитектура

```
                 горячая клавиша (ОС)
                         │
                         ▼
┌──────────── платформа (win / mac / linux) ────────────┐
│ hotkey · capture · overlay-окно · tray · clipboard    │
│ ocr · save-dialog · single-instance                   │
└──────┬───────────────────────────────▲────────────────┘
       │ кадр RGBA + геометрия мониторов│ готовый буфер пикселей
       ▼                               │
┌──────────────────── ядро (общее) ─────────────────────┐
│ session   — состояние: зона, инструмент, цвет, undo   │
│ annot     — модель пометок + отрисовка (tiny-skia)    │
│ toolbar   — раскладка панели, попадание кликов        │
│ redact    — правила «опасного» по словам OCR → рамки  │
│ export    — PNG без метаданных, имя файла             │
│ args, i18n                                            │
└───────────────────────────────────────────────────────┘
```

**Поток одного снимка**

1. Платформа ловит горячую клавишу → сразу снимает все мониторы в память (RGBA).
2. Показывает заранее созданное окно-оверлей поверх всех мониторов с «замороженным» кадром.
3. События мыши/клавиатуры → `session` (ядро). Ядро рисует кадр + затемнение + рамку + пометки + панель
   в буфер пикселей; платформа только выводит его на экран.
4. Enter / Ctrl+C → ядро «запекает» пометки и закраску в копию вырезанной зоны → `clipboard`.
   Ctrl+S → `export::png` → файл.
5. Оверлей прячется, все буферы затираются (`zeroize`), `session` сбрасывается.

### Модули ядра

| Модуль | Что делает | Тестируется |
|---|---|---|
| `args` | Разбор `--key`, `--key-screen`, `--key-window`, `--save-dir`, `--clear-clipboard`, `--no-detect`, `--lang`, `--help`; понятные ошибки | юнит |

| `session` | Состояние режима: зона, ручки рамки, инструмент, цвет, толщина, стек undo/redo, «последняя папка» | юнит |
| `annot` | Пометки (карандаш, линия, стрелка, прямоугольник, подпись, закраска) и их отрисовка; Shift-привязка к 0/45/90° | юнит + эталонные картинки |
| `toolbar` | Где поставить панель (снаружи рамки, перенос у края), какая кнопка под курсором | юнит |
| `redact` | Слова OCR с рамками → совпадения правил → объединённые прямоугольники с категорией | юнит, корпус примеров |
| `export` | PNG без `tEXt/iTXt/zTXt/tIME/eXIf`; имя `Зырик_ГГГГ-ММ-ДД_чч-мм-сс[_N].png` | юнит (проверка чанков) |

## Ключевые решения

| # | Решение | Почему | Отвергнутая альтернатива |
|---|---|---|---|
| D1 | **Rust**, структура как у Зябры | Общий опыт, общий CI, один файл без рантайма, x11rb/objc/windows уже освоены | C#/.NET (нет нормального Linux/macOS UI в одном файле), Go (слабые биндинги к ОС) |
| D2 | **Своя прослойка под ОС** вместо winit/egui/Tauri | Оверлей поверх всего, захват и буфер с флагами приватности всё равно пишутся вручную; фреймворк добавит веса и сетевых зависимостей у тянущихся crate'ов | winit + softbuffer — запасной вариант, если оверлей на Wayland окажется слишком сложным |
| D3 | **Рисование программно** в буфер RGBA: `tiny-skia` (линии, стрелки, сглаживание), `fontdue` + встроенный шрифт с кириллицей (Noto Sans / Inter, OFL, урезанный набор глифов) | Один код отрисовки на все ОС, пиксель в пиксель, тестируется эталонными PNG | Нативное рисование каждой ОС (три реализации, разный вид) |
| D4 | **Свой OCR: Tesseract + Leptonica, собранные статически и вшитые в бинарник вместе с моделями `eng` и `rus` (tessdata_fast)**. Модели читаются из памяти, на диск не распаковываются (R7) | Открытый код (Apache-2.0 / BSD-2): поведение проверяемо, как у Зябры. Одинаково на всех ОС, включая Linux, где системного OCR нет. Закрытые движки ОС не гарантируют, что ничего не хранят и не отправляют (история с `mediaanalysisd` на macOS в 2023 г.) | `Windows.Media.Ocr` / Vision — лучше качество и 0 МБ к размеру, но чёрный ящик. `ocrs` (чистый Rust) — нет кириллицы |
| D5 | **Поиск «опасного» — правила**: регулярки + валидаторы (Луна, СНИЛС, ИНН, Base58Check, Bech32, EIP-55) + словарь BIP-39 + энтропия | Предсказуемо, объяснимо, тестируется корпусом | ML-классификатор (непрозрачно, тяжело) |
| D6 | **Языки — таблицы, вшитые при сборке** | Многоязычность без чтения файлов с диска; пропущенный перевод ловится компилятором | gettext/fluent с файлами рядом с exe |
| D7 | **macOS — `Зырик.app` в zip** (без установки, просто распаковать) | Разрешение «Запись экрана» привязывается к приложению; голый бинарник из Терминала получит разрешение *Терминала* — это хуже для безопасности. **Нужно согласие владельца продукта: отклонение от FR-014** | Голый бинарник, как у Зябры |
| D8 | **Linux D-Bus — `zbus` (блокирующий API)** только в Linux-сборке | Порталы (GlobalShortcuts, FileChooser, ScreenCast), трей SNI | gtk (тяжело, тянет полстека) |

## Зависимости

Только эти; любая новая — через правку плана.

| Crate | Где | Зачем |

| `x11rb` | Linux | X11 (как в Зябре) |
| `wayland-client`, `wayland-protocols(-wlr)` | Linux | Wayland, layer-shell, screencopy |
| `zbus` | Linux | порталы, трей |
| `tiny-skia` | все | отрисовка пометок |
| `fontdue` | все | текст подписей и панели |
| `png` | все | запись PNG без метаданных |
| `regex` | все | правила «опасного» |
| `sha2`, `sha3` | все | контрольные суммы адресов кошельков |
| `zeroize` | все | затирание буферов |
| `flate2` | сборка + все | как в Зябре — сжатие встроенных данных (BIP-39, шрифт, модели OCR) и распаковка в память |

Ни у одной зависимости не должно быть сетевых возможностей; `cargo tree` проверяется в CI на
`reqwest|hyper|ureq|curl|native-tls|rustls|tokio-…net`.

### Итоги

**R1 — частично отвечено (2026-11-20, `probes/hotkey-win`).** Windows 11 Pro 26300, «PrtScr открывает Ножницы» **выключено**. `RegisterHotKey(MOD_CONTROL | MOD_NOREPEAT, VK_SNAPSHOT)` регистрируется, `WM_HOTKEY` приходит сразу; срабатывает и на нажатие через `SendInput`, поэтому самопроверку можно гонять в CI, в отличие от хука Зябры. Попутно выяснилось, что голый `PrtScr` и `Shift+PrtScr` уже заняты Lightshot (ошибка `0x80070581`, ERROR_HOTKEY_ALREADY_REGISTERED). Это реальный конфликт, и он подтверждает выбор `Ctrl+PrtScr` по умолчанию. Тот же код ошибки — сигнал для сообщения «клавиша занята» (история 8, сценарий 3).
*Осталось:* прогнать `hotkey-win --listen 15` руками при **включённых** «Ножницах»: Win+Shift+S в этой проверке не участвует, вопрос только в том, перехватывает ли система `Ctrl+PrtScr` вместе с `PrtScr`.

**R6 — частично отвечено (2026-11-20, `probes/capture-win`).** На одном мониторе 1920×1080 при 100% (7,9 МБ RGBA) `BitBlt` с `CAPTUREBLT` в DIB-секцию занимает в медиане 33 мс, минимум 28 мс, максимум 61 мс (первый, холодный замер). Копия в `Vec` добавляет меньше 1 мс. Бюджет 200 мс (принцип II) выдерживается с шестикратным запасом. Если время растёт линейно по пикселям, 4K + FullHD (~41 МБ) дадут около 170 мс, то есть впритык.
*Осталось:* замер на 2 мониторах 4K 150% + FullHD. Если там больше 100 мс — пробовать DXGI Desktop Duplication (T002).

**R2, R3** — не начаты: нужна машина с Linux на Wayland (KDE 6, GNOME, Sway/Hyprland).

## Риски

| Риск | Чем грозит | Что делаем |
|---|---|---|
| Wayland/GNOME не даёт глобальную клавишу и захват без диалога | Хуже UX на GNOME | Честно в README; приоритет — Sway, Hyprland, KDE |
| OCR ошибается на мелком тексте (tessdata_fast хуже системных движков) | Пропуск опасного | Масштабирование перед распознаванием (R5); подсветка — помощь, а не гарантия: ручная закраска всегда доступна; в README без обещаний «найдём всё» |
| Tesseract нельзя загрузить из памяти без доработки | Модели пришлось бы класть на диск — нарушение принципа I | R7 до начала фазы 6; запасной путь — небольшой патч в `third_party/tesseract` (своё чтение `traineddata` из буфера) |
| Сборка C++ под три ОС усложняет CI | Медленные и хрупкие сборки | Кэш собранных библиотек в CI; OCR — за cargo-фичей `ocr`, без неё программа собирается и работает (ручная закраска) |
| Буфер на X11/Wayland живёт, пока жива программа | После «Выход» снимок пропадает из буфера | Нормально для программы в трее; при выходе — не передавать снимок менеджеру буфера (это и есть приватность) |
| Затирание памяти неполное (копии в ОС, композиторе, буфере обмена) | Остатки снимка вне нашего контроля | Затираем всё своё; в README честно: «в чужой памяти — вне нашего контроля» |
| ФИО по шаблонам находится плохо | Низкая полнота в категории | Отдельная метрика; не блокирует релиз |

## Проверки, которые встраиваем в CI

- `offline` — как в Зябре: grep по исходникам на сетевые API (`TcpStream`, `UdpSocket`, `WinHttp`, `URLSession`, …) + проверка `cargo tree` на сетевые crate'ы.
- `no-disk` — Linux: запуск под Xvfb + `strace -f -e trace=openat,creat,rename,unlink,connect`,
  сценарий «10 снимков без Ctrl+S» → допустимы только чтение и `AF_UNIX`; любая запись в файл = провал (SC-003, SC-004).
- `ocr-no-disk` — Linux: распознавание корпуса под `strace -f -e trace=file,network` — ни одного открытия файла после старта, ни одного сокета (R7).
- `png-clean` — тест: сохранённый PNG содержит только `IHDR`, `IDAT`, `IEND` (и `sRGB`, если нужно).
- `i18n` — сборка падает, если в каком-то языке нет ключа.
- `redact-corpus` — полнота ≥ 90% / ≥ 99% и ложные срабатывания ≤ 1 на снимок (SC-006, SC-008).
- Матрица сборки: windows-latest, ubuntu-latest, macos-latest; артефакты — как у Зябры.
